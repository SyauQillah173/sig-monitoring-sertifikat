CATATAN TEKNOLOGI PROYEK
SIG MONITORING SERTIFIKAT PRODUK DAN SISTEM SEMEN
==================================================

Tujuan file:
Catatan ini dipakai agar pengembangan proyek tetap konsisten dengan stack,
domain bisnis, struktur kode, desain UI, keamanan, dan fitur yang sudah dibangun.


1. IDENTITAS PROYEK
--------------------------------------------------
Nama aplikasi:
- SIG Monitoring Sertifikat

Domain aplikasi:
- Monitoring sertifikat produk semen dan sertifikat sistem manajemen pabrik/lokasi semen.

Fokus sertifikat produk:
- Sertifikat SNI
- Sertifikat TKDN
- Sertifikat Green Label
- Kategori semen
- Merek semen
- Lokasi pabrik
- LSPro
- Komoditi / jenis semen

Fokus sertifikat sistem:
- ISO 9001  : Sistem Manajemen Mutu
- ISO 14001 : Sistem Manajemen Lingkungan
- ISO 45001 : Sistem Manajemen K3
- ISO 50001 : Sistem Manajemen Energi
- ISO 37001 : Sistem Manajemen Anti Penyuapan
- ISO 27001 : Sistem Manajemen Keamanan Informasi

Catatan penting:
- Project ini bukan aplikasi pangan.
- Jangan gunakan istilah BPOM, halal, makanan, minuman, nutrisi, izin edar pangan, atau komposisi makanan pada UI utama.

8. SERTIFIKAT SISTEM ISO SEMEN
--------------------------------------------------
Konsep:
- Sertifikat sistem tetap masuk domain semen.
- Relasinya berada pada level lokasi/pabrik.
- Contoh: Pabrik Tuban punya ISO 9001, ISO 14001, ISO 27001, dan seterusnya.

Dashboard Sertifikat Sistem:
- Menampilkan kartu ISO 9001, 14001, 45001, 50001, 37001, 27001.
- Menampilkan lokasi/pabrik, status, tahap audit, tanggal berlaku, progress masa berlaku, dan tombol dokumen.

Data Sertifikat Sistem Semen menyimpan:
- lokasi_pabrik_id
- iso_standard_id
- nomor sertifikat
- lembaga sertifikasi
- tanggal terbit
- berlaku sampai
- tahap audit
- scope/cakupan produk semen
- tahun perolehan
- level sertifikasi: nasional / internasional
- kategori sertifikasi
- process owner
- nomor akreditasi
- public URL
- deskripsi
- file sertifikat private jika ada
- status/catatan

Timeline Audit ISO:
- Model: app/Models/SertifikatSistemAuditEvent.php
- Service: app/Services/SystemCertificateAuditTimelineService.php
- Tabel: sertifikat_sistem_audit_events
- Event: initial, surveilen_1, surveilen_2, renewal
- Bukti audit disimpan private dan download wajib auth + role admin/petugas.
- Dashboard Sertifikat Sistem menampilkan semua kombinasi ISO + lokasi/pabrik.

9. STATUS MASA BERLAKU
--------------------------------------------------
Status sertifikat semen dihitung dari kolom berlaku_sd:
- Aktif
- Akan Berakhir
- Kadaluarsa

Logika:
- Aktif: masa berlaku lebih dari 90 hari.
- Akan Berakhir: masa berlaku kurang dari atau sama dengan 90 hari.
- Kadaluarsa: tanggal berlaku sudah lewat.

Trait terkait:
- app/Models/Concerns/HasCertificateExpiryStatus.php

13. KEAMANAN DAN AUDIT
--------------------------------------------------
Auth:
- Laravel Fortify
- Reset password memakai kode 6 digit yang dikirim ke email terdaftar.
- 2FA memakai TOTP/authenticator app seperti Google Authenticator, Microsoft Authenticator, atau Authy.
- Jika 2FA sudah diaktifkan dan dikonfirmasi, login otomatis meminta kode 2FA setelah password benar.
- Recovery code tersedia untuk kondisi darurat.
- Email OTP login belum menjadi metode 2FA; email code saat ini dipakai untuk reset password.

Role:
- admin
- petugas

Middleware:
- app.role
- security headers
- rate limit untuk login, reset password, import, export, dan download dokumen

Private file:
- File sertifikat sensitif tidak boleh diakses langsung lewat /storage/uploads/sertifikat.
- Download file sertifikat asli harus lewat route controller yang wajib login dan cek role.
- Dokumen ringkasan PDF dibuat oleh sistem dari database dan template aktif.
- File sertifikat ISO dan bukti audit ISO hanya boleh didownload admin/petugas.
- Guest tidak boleh download file asli ISO/bukti audit.
- Landing publik tidak boleh menampilkan nomor sertifikat, file, bukti audit, catatan internal, atau path storage.

Audit:
- audit_logs
- app/Services/AuditLogger.php
- app/Models/Concerns/AuditsModelChanges.php

Audit mencatat:
- login
- logout
- gagal login berulang
- perubahan master data
- perubahan sertifikat
- download dokumen
- import/export data sensitif
- pengaturan email notifikasi
- upload/reset template sertifikat
- proses email notifikasi
- proses tindak lanjut Surveilen/Renewal ISO
- download file sertifikat ISO
- download bukti audit ISO
- perubahan CMS Pengaturan Sistem
- proses backup, download backup, delete backup, dan cleanup backup

Tabel:

Folder backup:
- storage/app/private/backups

Isi backup:
- database.sql
- metadata.json
- file private storage jika opsi aktif
- file public storage jika opsi aktif

Command:
- php artisan system:backup
- php artisan system:backup --force
- php artisan system:backup-cleanup

Schedule:
- system:backup setiap hari jam 01:30
- system:backup-cleanup setiap Senin jam 02:30

Catatan:
- Backup MySQL memakai mysqldump.
- Pada XAMPP Windows, sistem mencari C:\xampp\mysql\bin\mysqldump.exe.
- Jika lokasi mysqldump berbeda, bisa atur BACKUP_MYSQLDUMP_PATH di .env.
- Backup dibuat private dan hanya admin yang boleh download.
- Cleanup menghapus backup lama sesuai retensi dan maksimal jumlah backup.
- Health check menampilkan warning APP_DEBUG, user DB root, password DB kosong, backup terakhir, dan relasi data orphan.

Catatan ISO 27001:
- Lihat CATATAN_KEAMANAN_ISO27001.txt
- ISO 27001 bukan sekadar fitur kode, tetapi standar manajemen keamanan informasi organisasi.

17. CATATAN KONSISTENSI
--------------------------------------------------
- Tetap gunakan Laravel + Blade + Tailwind.
- Jangan pindah ke React/Vue tanpa keputusan besar.
- Jangan mengembalikan istilah pangan/BPOM/halal.
- Jangan hardcode data utama di frontend.
- Dashboard harus membaca database.
- Master data harus dipakai untuk field referensi.
- Import boleh membuat ID otomatis lewat database.
- Import tidak boleh membuat master baru otomatis dari text bebas.
- Import Excel boleh diketik manual, tetapi preview harus tetap menolak typo dan data di luar master aktif.
- Import Excel harus melewati data duplikat agar tidak membuat sertifikat ganda.
- Jangan hardcode password email.
- File sertifikat sensitif harus private download.
- Template sertifikat hanya background, data tetap dari database.
- Perubahan fitur penting perlu test.
- UI light dan dark harus selalu dicek bersamaan.
- Pengaturan Sistem adalah pusat CMS admin, jangan dicampur dengan Pengaturan Akun pribadi.
- Backup otomatis wajib tetap private dan tercatat audit log.
- Jangan simpan file backup di public folder.
