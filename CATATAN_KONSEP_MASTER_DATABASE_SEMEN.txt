CATATAN KONSEP MASTER DATABASE SEMEN
SIG MONITORING SERTIFIKAT
==================================================

Tujuan catatan ini:
Menjelaskan konsep menu Pemeliharaan Data, data master, asal ID master, sertifikat produk, sertifikat sistem ISO, import Excel, perusahaan/kontak email, dan template sertifikat agar tidak bingung saat mengubah atau menambah data.


1. APA ITU DATA MASTER?
--------------------------------------------------
Data master adalah data baku yang disimpan di database agar input sertifikat tidak bebas typo dan bisa dipanggil memakai ID.

Contoh:
- Kategori semen disimpan di tabel kategori_semen.
- Merek semen disimpan di tabel merek_semen.
- Lokasi pabrik disimpan di tabel lokasi_pabrik.
- Referensi SNI, Komoditi, LSPro, Jenis Sertifikasi, Kemasan, dan Peringkat Green Label disimpan di tabel cement_reference_values.
- Standar ISO sistem semen disimpan di tabel iso_standards.

Jadi kata "Master" di aplikasi artinya bukan sertifikat baru, tapi daftar pilihan baku yang nanti dipakai saat input sertifikat.


2. KENAPA ADA ID MASTER?
--------------------------------------------------
ID master dibuat otomatis oleh database. ID ini dipakai sebagai penghubung antar tabel.

Contoh:
- Sertifikat SNI menyimpan merek_semen_id agar tahu mereknya dari tabel merek_semen.
- Sertifikat SNI menyimpan sni_reference_id agar tahu standar SNI dari tabel cement_reference_values.
- Sertifikat Sistem menyimpan lokasi_pabrik_id dan iso_standard_id agar tahu lokasi dan ISO-nya dari tabel master.

Admin tidak perlu mengetik ID secara manual. ID muncul otomatis setelah data master atau sertifikat berhasil disimpan.


3. KENAPA ID LANGSUNG 21 ATAU 23, BUKAN MULAI 1?
--------------------------------------------------
Karena tabel cement_reference_values menyimpan banyak jenis referensi dalam satu tabel.

Contoh urutan data seed:
- ID 1 sampai 11: master SNI
- ID 12 sampai 18: master Komoditi / Jenis Semen
- ID 19 sampai 21: master LSPro
- ID 22 sampai 23: master Jenis Sertifikasi
- ID 24 sampai 28: master Kemasan
- ID 29: master Peringkat Green Label

Jadi kalau Jenis Sertifikasi mulai dari ID 22, itu normal karena ID sebelumnya sudah dipakai oleh master SNI, Komoditi, dan LSPro.


4. MENU MASTER REFERENSI DIPAKAI UNTUK APA?
--------------------------------------------------
Menu berikut dipakai untuk mengelola pilihan baku sertifikat produk:
- Master SNI Semen
- Master Komoditi / Jenis Semen
- Master LSPro
- Master Jenis Sertifikasi
- Master Kemasan
- Master Peringkat Green Label

Menu berikut dipakai untuk sertifikat sistem:
- Master Standar ISO Sistem Semen

Saat admin menambah sertifikat, pilihan di form diambil dari menu master ini.

Kalau ada data baru dari dokumen asli, misalnya LSPro baru, admin bisa menambahkan dulu di Master LSPro. Setelah itu LSPro tersebut bisa dipilih saat input sertifikat.


5. ALUR DATA SERTIFIKAT PRODUK
--------------------------------------------------
Sertifikat SNI mengambil data dari:
- merek_semen_id dari tabel merek_semen
- sni_reference_id dari master SNI
- komoditi_reference_id dari master Komoditi
- jenis_sertifikasi_reference_id dari master Jenis Sertifikasi
- lspro_reference_id dari master LSPro
- lokasi_pabrik_id dari tabel lokasi_pabrik

Sertifikat TKDN mengambil data dari:
- merek_semen_id dari tabel merek_semen
- sni_reference_id dari master SNI
- komoditi_reference_id dari master Komoditi
- kemasan_reference_id dari master Kemasan
- lokasi_pabrik_id dari tabel lokasi_pabrik

Sertifikat Green Label mengambil data dari:
- merek_semen_id dari tabel merek_semen
- sni_reference_id dari master SNI
- komoditi_reference_id dari master Komoditi
- peringkat_green_label_reference_id dari master Peringkat Green Label
- lokasi_pabrik_id dari tabel lokasi_pabrik


6. ALUR DATA SERTIFIKAT SISTEM ISO SEMEN
--------------------------------------------------
Sertifikat Sistem ISO tetap masuk domain semen, tetapi tidak ditempel langsung ke merek semen.

Konsep yang dipakai:
- ISO adalah sertifikat sistem manajemen.
- Relasinya paling tepat berada di level pabrik/lokasi.
- Contoh: Pabrik Tuban memiliki ISO 9001, ISO 14001, ISO 27001, dan seterusnya.

Sertifikat Sistem Semen mengambil data dari:
- lokasi_pabrik_id dari tabel lokasi_pabrik
- iso_standard_id dari tabel iso_standards
- nomor sertifikat
- lembaga sertifikasi
- tanggal terbit
- tanggal berlaku sampai
- tahap audit: Surveilen 1, Surveilen 2, atau Renewal
- scope/cakupan, misalnya Produksi semen
- file sertifikat asli jika ada
- tahun perolehan
- level sertifikasi: nasional atau internasional
- kategori sertifikasi
- process owner
- nomor akreditasi
- public URL jika ada
- deskripsi korporasi

Sertifikat Sistem ISO juga memiliki timeline audit terpisah di tabel sertifikat_sistem_audit_events.

Timeline audit berisi:
- initial / sertifikasi awal
- surveilen 1
- surveilen 2
- renewal

Sistem menghitung target timeline dari tanggal terbit dan tanggal berlaku sampai. Admin/petugas tetap harus melakukan konfirmasi manual saat audit selesai, termasuk upload bukti audit jika ada.

Master ISO awal:
- ISO 9001  : Sistem Manajemen Mutu
- ISO 14001 : Sistem Manajemen Lingkungan
- ISO 45001 : Sistem Manajemen K3
- ISO 50001 : Sistem Manajemen Energi
- ISO 37001 : Sistem Manajemen Anti Penyuapan
- ISO 27001 : Sistem Manajemen Keamanan Informasi


7. PERUSAHAAN SEMEN DAN KONTAK EMAIL PERUSAHAAN
--------------------------------------------------
Perusahaan Semen adalah data perusahaan penerima notifikasi atau pemilik kontak.

Untuk menambah nama perusahaan:
1. Buka Pemeliharaan Data.
2. Pilih kartu "Perusahaan Semen".
3. Klik "Tambah Perusahaan".
4. Isi nama perusahaan, kode jika ada, alamat jika ada, dan status aktif.

Setelah perusahaan dibuat, baru bisa menambah kontak email perusahaan:
1. Buka Pemeliharaan Data.
2. Pilih kartu "Kontak Email Perusahaan".
3. Klik "Tambah Kontak".
4. Pilih perusahaan yang sudah dibuat.
5. Isi Nama PIC, Jabatan, Email, Telepon, Kontak Utama, dan Status.

Kalau dropdown perusahaan kosong saat tambah kontak, penyebabnya biasanya belum ada Perusahaan Semen aktif.


8. PERBEDAAN LOKASI PABRIK DAN PERUSAHAAN SEMEN
--------------------------------------------------
Lokasi Pabrik adalah tempat/pabrik pada data sertifikat, contoh: Pabrik Tuban.

Perusahaan Semen adalah nama perusahaan untuk kebutuhan kontak dan notifikasi email.

Keduanya berbeda:
- Lokasi dipakai oleh sertifikat produk dan sertifikat sistem.
- Perusahaan dipakai untuk mengelompokkan kontak email penerima reminder.


9. IMPORT EXCEL DAN ID OTOMATIS
--------------------------------------------------
Admin tidak perlu mengetik ID database di Excel.

Konsep import terbaru:
- Admin bisa memilih dari dropdown template atau mengetik manual di Excel.
- Saat import berhasil, ID dibuat otomatis oleh database.
- Sistem mencocokkan nama kategori, merek, lokasi, SNI, LSPro, dan master lain.
- Data yang diketik manual boleh masuk selama ejaannya cocok dengan master/contoh.
- Jika nilai tidak cocok master aktif, preview import akan menolak data agar typo/text bebas tidak masuk database.
- Import tidak membuat master baru otomatis. Master baru harus ditambahkan dulu dari Pemeliharaan Data.
- Template Excel berisi 2 baris contoh pada setiap sheet sertifikat sebagai panduan pengisian.
- Dropdown Excel bersifat bantuan. Jika user mengetik manual, Excel hanya memberi warning; validasi utama tetap di web saat Preview Data.
- File sertifikat pada Excel opsional. Untuk import biasa kolom file_sertifikat dikosongkan, lalu upload PDF/JPG/PNG dari menu Edit Sertifikat setelah data tersimpan.
- Sistem mendeteksi data duplikat. Data yang sudah ada di sistem atau dobel di file Excel dilewati, hanya data baru yang disimpan.

Artinya:
- Excel dipakai untuk input data.
- Database yang membuat ID.
- Dashboard membaca data yang sudah masuk secara dinamis.
- Database tetap bersih karena import tidak menerima text bebas dan tidak membuat master dari typo.


10. DOKUMEN SERTIFIKAT DAN TEMPLATE
--------------------------------------------------
Ada dua jenis dokumen:

1. File sertifikat asli
- Ini adalah file dari lembaga sertifikasi.
- Bisa PDF/JPG/PNG.
- Disimpan private.
- Download harus lewat login dan role sesuai.

2. Dokumen ringkasan sertifikat dari sistem
- Dibuat otomatis oleh aplikasi.
- Data diambil dari database.
- Background memakai template sertifikat.
- Bisa didownload dari tombol Dokumen.

Template sertifikat:
- Default ada di public/images/Sertifikat.optimized.jpg.
- Admin bisa upload template baru dari:
  Pemeliharaan Data > Template Sertifikat
- Upload template hanya mengganti background.
- Posisi teks tetap dari layout sistem.
- Template paling aman portrait A4 dan area tengah kosong.
- Template akan dikompres otomatis agar PDF tetap aman saat berjalan di Vercel.


11. NOTIFIKASI INTERNAL DAN EMAIL TINDAK LANJUT ISO
--------------------------------------------------
Notifikasi terbaru difokuskan dulu untuk Sertifikat Sistem ISO.

Konsep:
- Sistem membaca data sertifikat_sistem_semen.
- Jika ada sertifikat perlu Surveilen 1, Surveilen 2, atau Renewal, sistem membuat notifikasi internal.
- Notifikasi internal dikirim ke user role admin dan petugas.
- Email reminder juga dikirim ke kontak/penerima yang aktif.

Data aksi disimpan di tabel notifications pada kolom data, misalnya:
- certificate_type: system
- certificate_id: ID sertifikat sistem
- iso_code: ISO 9001 / ISO 14001 / dan seterusnya
- location: lokasi/pabrik
- follow_up_action: surveilen_1, surveilen_2, atau renewal
- action_url: link form tindak lanjut di web
- target_date: tanggal target tindak lanjut

Alur aksi:
- Ubah Status S1 membuka form konfirmasi Surveilen 1.
- Ubah Status S2 membuka form konfirmasi Surveilen 2.
- Input Data Baru membuka form Renewal.
- Klik dari email tidak langsung mengubah database.
- Data berubah hanya setelah admin/petugas submit form di web.

Khusus Renewal:
- Sistem membuat record sertifikat_sistem_semen baru.
- Data lama diprefill agar admin tidak mengetik ulang semua field.
- Admin mengisi nomor sertifikat baru, tanggal baru, catatan/scope jika perlu, dan file sertifikat baru jika ada.
- Record lama tetap ada sebagai riwayat.


12. CMS PENGATURAN SISTEM
--------------------------------------------------
Pengaturan Sistem adalah CMS admin yang terpisah dari Pengaturan Akun.

Pengaturan Akun hanya untuk profil, password, dan 2FA user pribadi.

Pengaturan Sistem dipakai admin untuk:
- Manajemen User
- Tampilan Publik sebelum login
- Menu Aplikasi / sidebar setelah login
- Backup & Maintenance
- Email & Notifikasi
- Template Sertifikat
- Pemeliharaan Data

Tabel yang dipakai:
- system_settings untuk setting global CMS
- navigation_items untuk menu sidebar dinamis berbasis role
- database_backups untuk riwayat backup sistem

Catatan:
- Route menu aplikasi dibuat tetap/fixed agar admin tidak salah ubah route.
- Admin hanya mengubah label, group, icon, urutan, role, dan status aktif.
- Icon dipilih dari daftar icon yang disediakan sistem, bukan upload bebas.
- Jika navigation_items kosong, sidebar memakai fallback dari kode agar aplikasi tetap bisa dipakai.


13. PRIVASI LANDING SEBELUM LOGIN
--------------------------------------------------
Landing sebelum login membaca ringkasan data dari database, tetapi tidak boleh membocorkan data rahasia.

Admin bisa mengatur dari:
Pengaturan Sistem > Tampilan Publik

Yang bisa dinyalakan/dimatikan:
- Ringkasan Angka
- Status Monitoring
- Komposisi Dokumen
- Distribusi Jenis Sertifikat
- Sertifikasi Sistem ISO
- Prioritas Operasional

Khusus data ISO publik, admin juga bisa mengatur apakah detail berikut boleh tampil:
- Lokasi / Pabrik
- Lembaga Sertifikasi
- Scope
- Masa Berlaku
- Status
- Tahun & Level
- Kategori Sertifikasi

Yang tetap tidak boleh tampil di landing:
- nomor sertifikat asli
- file sertifikat
- bukti audit
- catatan internal
- path file storage


14. AUDIT LOG DAN BACKUP SISTEM
--------------------------------------------------
Audit log masuk ke tabel audit_logs.

Audit log mencatat:
- login/logout/gagal login
- CRUD master data
- CRUD sertifikat
- download file sertifikat sensitif
- download bukti audit ISO
- perubahan CMS
- proses backup
- download/hapus backup

Backup sistem masuk ke:
- tabel database_backups untuk riwayat
- folder storage/app/private/backups untuk file backup

Isi backup:
- dump database
- metadata backup
- file private sertifikat dan bukti audit jika opsi "Sertakan file private" aktif
- file public storage jika ada

Backup bisa dibuat dari:
Pengaturan Sistem > Backup & Maintenance

Backup otomatis dijalankan oleh scheduler Laravel:
- command: php artisan system:backup
- schedule: setiap hari jam 01:30

Cleanup backup:
- command: php artisan system:backup-cleanup
- menghapus backup lama sesuai retensi dan maksimal jumlah backup
- menghapus record backup sukses yang filenya sudah hilang


15. APP_URL DAN LINK EMAIL
--------------------------------------------------
Link pada email dibuat dari APP_URL di file .env.

Jika server lokal jalan di:

http://127.0.0.1:8082

maka .env harus berisi:

APP_URL=http://127.0.0.1:8082

Jika APP_URL masih localhost:8000, email akan membuka port 8000 dan bisa gagal dengan ERR_CONNECTION_REFUSED.

Setelah mengubah APP_URL:
- Jalankan php artisan config:clear
- Jalankan php artisan optimize:clear
- Kirim ulang email notifikasi

Email lama yang sudah masuk tidak bisa otomatis berubah link-nya.


16. STATUS MASA BERLAKU
--------------------------------------------------
Status sertifikat dihitung dari tanggal berlaku sampai:
- Aktif
- Akan Berakhir
- Kadaluarsa

Logika:
- Aktif jika masa berlaku masih lebih dari 90 hari.
- Akan Berakhir jika masa berlaku kurang dari atau sama dengan 90 hari.
- Kadaluarsa jika tanggal berlaku sudah lewat.
