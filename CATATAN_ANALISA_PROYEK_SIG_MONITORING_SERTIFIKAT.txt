1. IDENTITAS PROYEK
--------------------------------------------------
Nama aplikasi:
SIG Monitoring Sertifikat

Jenis aplikasi:
Web dashboard untuk monitoring sertifikat produk semen dan sertifikat sistem manajemen ISO pada lokasi/pabrik semen.

Domain utama:
- Sertifikat Produk Semen
- Sertifikat Sistem ISO Semen
- Monitoring masa berlaku sertifikat
- Reminder Surveilen 1, Surveilen 2, dan Renewal
- Pengelolaan dokumen/file sertifikat
- Export, import, audit log, dan backup sistem

Target pengguna:
- Admin
- Petugas

Tujuan utama aplikasi:
- Membantu perusahaan memantau sertifikat produk semen dan sistem ISO secara terpusat.
- Mengurangi risiko sertifikat terlambat diperpanjang.
- Menyediakan data, laporan, dokumen, reminder email, dan notifikasi internal dalam satu sistem.


2. MASALAH YANG DISELESAIKAN
--------------------------------------------------
Sebelum ada aplikasi:
- Data sertifikat bisa tersebar di Excel, file lokal, email, atau folder manual.
- Risiko typo tinggi karena input bebas.
- Sulit memantau sertifikat yang akan habis masa berlakunya.
- Reminder Surveilen/Renewal bisa terlupakan.
- File sertifikat dan bukti audit bisa sulit ditemukan.
- Laporan perlu dibuat manual.
- Tidak ada audit log yang jelas untuk aktivitas penting.

Setelah ada aplikasi:
- Data sertifikat disimpan di database.
- Master data dipakai agar input konsisten.
- Dashboard menampilkan status sertifikat secara otomatis.
- Email dan Notifikasi Internal mengingatkan tindak lanjut ISO.
- File sertifikat dan bukti audit disimpan private.
- Export Excel/PDF tersedia.
- Aktivitas penting tercatat di audit log.
- Backup sistem bisa dibuat manual dan otomatis.

6. KEUNIKAN PROYEK
--------------------------------------------------
Keunikan proyek ini:

1. Domain khusus semen
Proyek ini tidak generic. Data dan istilah diarahkan khusus untuk monitoring sertifikat semen, seperti SNI semen, TKDN semen, Green Label semen, lokasi pabrik, dan ISO sistem semen.

2. Menggabungkan sertifikat produk dan sistem ISO
Aplikasi tidak hanya memantau sertifikat produk, tetapi juga sertifikat sistem ISO per lokasi/pabrik.

3. Anti-typo dengan master data
Input penting tidak dibiarkan bebas. Master data dipakai untuk menjaga konsistensi penulisan.

4. Import Excel tetap aman
User boleh mengetik manual di Excel, tetapi validasi utama ada di Preview Data pada web. Ini membuat import fleksibel tetapi tetap terkendali.

5. Reminder dua kanal
Reminder ISO tidak hanya lewat email, tetapi juga masuk ke Notifikasi Internal aplikasi.

6. Tindak lanjut tidak one-click
Link email atau notifikasi tidak langsung mengubah database. User tetap harus login dan submit form web. Ini lebih aman dan bisa diaudit.

7. Vercel-safe storage
Karena Vercel serverless tidak cocok untuk menyimpan file lokal jangka panjang, file baru di production bisa disimpan ke tabel stored_files.

8. Dokumen PDF berbasis template
Sistem bisa membuat dokumen ringkasan sertifikat otomatis dari data database dan template background.

9. CMS pengaturan sistem
Admin bisa mengatur tampilan publik, menu aplikasi, email, template, backup, dan maintenance dari web.

10. Audit dan backup
Aktivitas penting dicatat, dan backup sistem bisa dijalankan manual maupun otomatis.


7. KEAMANAN YANG DIPAKAI
--------------------------------------------------
7.1 Autentikasi
- Laravel Fortify.
- Login email dan password.
- Password di-hash oleh Laravel.
- Reset password memakai kode 6 digit.
- Two Factor Authentication berbasis TOTP/authenticator app.
- Recovery code tersedia untuk 2FA.

7.2 Otorisasi Role
- Role admin.
- Role petugas.
- Spatie Laravel Permission untuk role/permission.
- Middleware app.role untuk membatasi akses menu/route.

Contoh pembagian:
- Admin bisa akses pemeliharaan data, import, export, user management, pengaturan sistem, backup.
- Petugas bisa melihat dan memproses bagian operasional sesuai akses.

7.3 Middleware dan Rate Limit
- auth untuk route yang butuh login.
- verified untuk beberapa route akun.
- password.confirm untuk bagian security.
- throttle untuk route sensitif.
- throttle:sensitive-download untuk download file.
- throttle:sensitive-import untuk import dan proses berat.
- throttle:sensitive-export untuk export.

7.4 Proteksi CSRF
- Form POST/PUT/PATCH/DELETE memakai CSRF token Laravel.
- Tindak lanjut Surveilen/Renewal harus submit form web.

7.5 File Private
- File sertifikat asli tidak boleh public langsung.
- File bukti audit ISO tidak boleh public langsung.
- Download lewat controller yang cek login dan role.
- Pada Vercel file baru bisa disimpan di database melalui stored_files.

7.6 Audit Log
Audit log mencatat:
- login
- logout
- gagal login
- perubahan data
- import/export
- download file sensitif
- pengaturan email
- reminder email
- upload/reset template
- backup
- tindak lanjut ISO

7.7 Security Headers
- Middleware AddSecurityHeaders menambahkan header keamanan.
- Tujuannya mengurangi risiko browser attack dasar.

7.8 Backup Private
- Backup disimpan di storage private.
- Backup hanya boleh diakses admin.
- Download/hapus backup dicatat audit log.

7.9 Cron Secret
- Endpoint cron Vercel memakai CRON_SECRET.
- Request tanpa Authorization yang sesuai ditolak.

7.10 Catatan Risiko Keamanan
- APP_DEBUG harus false di production.
- .env tidak boleh dipush ke GitHub.
- Password SMTP/App Password tidak boleh ditulis di kode.
- File backup dan file sertifikat tidak boleh berada di public folder.

10. FRAMEWORK UNTUK MENGHITUNG DATA
--------------------------------------------------
Pertanyaan:
Framework untuk menghitung data itu pakai apa dan bahasa apa?

Jawaban:
Perhitungan data utama dilakukan di backend menggunakan PHP dengan Laravel.

Bagian yang dipakai:
- Eloquent ORM
- Laravel Query Builder
- Laravel Collection
- Service class seperti CementDashboardService dan LandingPageSummaryService
- SQL aggregate dari MySQL/TiDB seperti count, group by, dan query relasi

Contoh data yang dihitung:
- Total merek.
- Total sertifikat SNI.
- Total sertifikat TKDN.
- Total Green Label.
- Total sertifikat ISO.
- Status Aktif/Akan Berakhir/Kadaluarsa.
- Persentase chart/donut.
- Jumlah data per jenis sertifikat.
- Data sertifikat yang mendekati masa berlaku habis.
- Jumlah dokumen yang tersedia.

Logika status masa berlaku:
- Aktif jika masa berlaku masih lebih dari 90 hari.
- Akan Berakhir jika sisa masa berlaku kurang dari atau sama dengan 90 hari.
- Kadaluarsa jika tanggal berlaku sudah lewat.

Catatan:
Excel hanya membantu input dan export. Perhitungan utama aplikasi tetap dilakukan oleh Laravel/PHP dan database, bukan oleh Excel.

24. SARAN PENINGKATAN KEAMANAN
--------------------------------------------------
Walaupun proyek ini sudah memakai login, role, private download, audit log, 2FA, rate limit, dan backup, keamanan masih bisa ditingkatkan lagi. Berikut saran peningkatan keamanan yang cocok untuk pengembangan berikutnya.

24.1 Wajibkan 2FA untuk Admin
- Saat ini 2FA tersedia, tetapi bisa dibuat wajib untuk role admin.
- Tujuannya agar akun admin tetap aman walaupun password bocor.
- Petugas bisa dibuat opsional, sedangkan admin wajib.

24.2 Gunakan Object Storage Private untuk File Besar
- Untuk production jangka panjang, file sertifikat dan bukti audit sebaiknya disimpan di object storage private seperti S3, Vercel Blob private, atau storage lain yang mendukung signed URL.
- Database storage cocok untuk file kecil/menengah, tetapi object storage lebih baik untuk file besar.
- Download tetap lewat controller agar role dan audit log tetap berjalan.

24.3 Enkripsi File Sensitif
- File sertifikat dan bukti audit bisa dienkripsi sebelum disimpan.
- Jika storage bocor, isi file tetap tidak langsung terbaca.
- Kunci enkripsi harus disimpan aman di environment variable, bukan di kode.

24.4 Antivirus / File Scanning Upload
- File upload sebaiknya discan sebelum diterima.
- Tujuannya mencegah upload file berbahaya yang menyamar sebagai PDF/JPG/PNG.
- Validasi MIME dan ekstensi sudah membantu, tetapi scanning memberi lapisan tambahan.

24.5 Batasi Ukuran dan Jenis File Lebih Ketat
- Tetapkan batas upload production yang konservatif.
- Contoh Vercel: 3 MB untuk sertifikat.
- Tolak file yang tidak sesuai MIME asli.
- Hindari menerima file executable, script, atau archive bebas.

24.6 Session Security Lebih Ketat
- Production harus memakai HTTPS.
- Aktifkan SESSION_SECURE_COOKIE=true.
- Aktifkan cookie HttpOnly dan SameSite sesuai konfigurasi Laravel.
- Session lifetime bisa dipersingkat untuk akun admin.

24.7 Password Policy Lebih Kuat
- Terapkan minimum panjang password.
- Wajib kombinasi huruf besar, huruf kecil, angka, dan simbol.
- Tolak password yang terlalu umum.
- Tambahkan fitur ganti password berkala jika dibutuhkan kebijakan perusahaan.

24.8 Account Lockout dan Deteksi Gagal Login
- Rate limit login sudah ada, tetapi bisa ditambah account lockout sementara.
- Jika gagal login berkali-kali, akun dikunci sementara.
- Admin menerima notifikasi jika ada percobaan login mencurigakan.

24.9 Audit Log Lebih Detail dan Tidak Mudah Dihapus
- Audit log sebaiknya tidak bisa dihapus dari UI biasa.
- Jika perlu retensi, hapus lewat kebijakan terjadwal dan tercatat.
- Audit log penting bisa dikirim ke log eksternal agar tidak hilang jika database bermasalah.

24.10 Monitoring Aktivitas Mencurigakan
- Tambahkan dashboard keamanan sederhana.
- Contoh data:
  - gagal login terbanyak
  - download file sensitif terbanyak
  - perubahan data penting terbaru
  - akses dari IP tidak biasa
  - aktivitas admin di luar jam kerja

24.11 Approval untuk Aksi Sensitif
- Beberapa aksi penting bisa dibuat butuh approval dua tahap.
- Contoh:
  - hapus sertifikat
  - hapus user
  - reset template sertifikat
  - download backup
  - ubah pengaturan email

24.12 Backup Encryption
- File backup berisi database dan file private, sehingga sebaiknya dienkripsi.
- Backup juga sebaiknya punya password kuat atau encryption key.
- Download backup tetap hanya admin dan tercatat audit log.

24.13 Backup Offsite
- Selain backup lokal/private storage, simpan salinan backup ke lokasi lain.
- Contoh:
  - cloud storage
  - server backup internal
  - storage khusus backup
- Tujuannya agar data tetap aman jika server utama rusak.

24.14 Proteksi Cron Endpoint
- Endpoint cron sudah memakai CRON_SECRET.
- Ke depan bisa ditambah:
  - rotasi secret berkala
  - pembatasan IP jika memungkinkan
  - audit log setiap cron dijalankan
  - alert jika cron gagal

24.15 Security Header Lebih Lengkap
- Pastikan header berikut sesuai kebutuhan production:
  - Content-Security-Policy
  - X-Frame-Options atau frame-ancestors pada CSP
  - X-Content-Type-Options
  - Referrer-Policy
  - Permissions-Policy
  - Strict-Transport-Security untuk HTTPS

24.16 Content Security Policy Lebih Ketat
- CSP membantu mencegah XSS.
- Untuk production, batasi script, style, image, dan font hanya dari sumber yang dibutuhkan.
- Jika memakai CDN, masukkan domain CDN secara eksplisit.

24.17 Validasi dan Sanitasi Input Lebih Ketat
- Semua input user harus divalidasi di server.
- Field teks panjang seperti catatan, scope, deskripsi, dan nama lembaga harus punya batas panjang.
- Output di Blade harus tetap memakai escaping default Laravel.

24.18 Least Privilege untuk Database
- User database production jangan memakai root.
- Buat user database khusus aplikasi.
- Berikan hak akses secukupnya.
- Password database harus kuat dan tidak dibagikan.

24.19 Pemisahan Environment
- Local, staging, dan production harus punya environment berbeda.
- Database testing/staging jangan memakai database production.
- APP_DEBUG wajib false di production.

24.20 Secret Management
- Secret seperti SMTP password, DB password, CRON_SECRET, dan APP_KEY harus disimpan di environment provider.
- Jangan menulis secret di dokumentasi, screenshot, GitHub, atau chat publik.
- Jika secret pernah bocor, segera rotate/ganti.

24.21 Penetration Testing Ringan
- Lakukan pengujian keamanan dasar:
  - coba akses route admin tanpa login
  - coba download file tanpa login
  - coba upload file ekstensi palsu
  - coba input script pada form
  - coba brute force login
  - coba akses backup dari URL langsung

24.22 Dependency Security Check
- Jalankan pemeriksaan dependency secara berkala.
- Untuk PHP gunakan:
  composer audit
- Untuk Node gunakan:
  npm audit
- Update dependency jika ada vulnerability penting.

24.23 Logging Error Production
- Jangan tampilkan stack trace ke user production.
- APP_DEBUG=false wajib.
- Error detail cukup masuk log.
- User cukup melihat halaman error umum.

24.24 Retensi Notifikasi dan Audit
- Notifikasi lama yang sudah dibaca bisa disembunyikan setelah periode tertentu, misalnya 90 hari.
- Audit log sebaiknya punya retensi lebih panjang karena berhubungan dengan keamanan.
- Retensi harus jelas antara notifikasi operasional dan audit keamanan.

24.25 Dokumentasi SOP Keamanan
- Buat SOP untuk:
  - membuat user admin
  - menonaktifkan akun petugas keluar
  - reset password
  - restore backup
  - menangani file sertifikat sensitif
  - menangani kebocoran akun

Ringkasan:
Peningkatan keamanan paling prioritas adalah mewajibkan 2FA untuk admin, memastikan APP_DEBUG=false di production, memakai storage private yang lebih kuat untuk file besar, mengenkripsi backup, memperketat upload file, dan membuat monitoring aktivitas mencurigakan.


25. RINGKASAN UNTUK PRESENTASI
--------------------------------------------------
SIG Monitoring Sertifikat adalah aplikasi web berbasis Laravel yang digunakan untuk memantau sertifikat produk semen dan sertifikat sistem ISO pada lokasi/pabrik semen. Aplikasi ini menyediakan dashboard, master data anti-typo, import Excel, export Excel/PDF, dokumen sertifikat otomatis, reminder email, Notifikasi Internal, audit log, dan backup sistem.

Input utama aplikasi adalah data master, data sertifikat, file sertifikat, file bukti audit, template sertifikat, file Excel, dan konfigurasi email. Output utama aplikasi adalah dashboard monitoring, status masa berlaku, laporan Excel/PDF, dokumen ringkasan sertifikat, email reminder, Notifikasi Internal, audit log, dan backup.

Keunikan aplikasi ini adalah fokus pada domain semen, menggabungkan sertifikat produk dan sistem ISO, memiliki reminder Surveilen/Renewal dua kanal, serta menjaga file sensitif tetap private. Perhitungan data dilakukan oleh PHP Laravel melalui Eloquent, Query Builder, Collection, dan database MySQL/TiDB.


26. KESIMPULAN

- dokumen PDF
